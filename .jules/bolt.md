## 2024-05-24 - Optimizing Nuxt Nitro JSON Data Loading
**Learning:** In Nuxt's Nitro server, using `fs.readFile` alongside `process.cwd()` to load static JSON data for API responses is highly inefficient. It incurs significant I/O overhead on every request and poses risks in production deployments where `process.cwd()` might not point to the original source structure. A much better pattern is to use ES module imports directly (e.g., `import data from '../data.json'`). Nitro automatically bundles and caches this imported JSON data in memory, making subsequent requests incredibly fast. However, it's crucial to remember that this cached object is shared across requests; direct mutations will persist. Non-mutating methods (like `.filter()`) must be used for data manipulation.
**Action:** Replace `fs.readFile` with direct ES module JSON imports for static data in API routes. Always ensure non-mutating operations are used on the imported, cached data.
