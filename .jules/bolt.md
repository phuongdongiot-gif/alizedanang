## 2024-05-27 - [Direct JSON ES module import vs fs.readFile in Nuxt Nitro]
**Learning:** Using `fs.readFile` and `JSON.parse` with `process.cwd()` inside Nitro handlers forces synchronous-like file reading on every API request and relies on the raw file existing relative to `process.cwd()`. In Nuxt serverless production builds, raw files in `server/data/` might not even be bundled or accessible from `process.cwd()`. By changing to a static ES module import (`import data from '../data/data.json'`), the file is read and parsed only once at startup, natively bundled by Nuxt, and cached in memory for significantly faster response times without risking path resolution issues.
**Action:** When working in Nuxt or any bundler-driven environment, prefer direct ES module static imports for JSON data over runtime file system reads (`fs.readFile`) whenever the data does not change at runtime.
