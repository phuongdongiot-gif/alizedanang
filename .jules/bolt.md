## 2024-06-22 - Replacing fs.readFile with Direct JSON Imports in Nuxt Nitro
**Learning:** Nuxt's Nitro server natively supports ES module imports of JSON files (e.g., `import data from '../data.json'`), automatically bundling and caching the data in memory. This is significantly faster and more bundler-friendly than using dynamic `fs.readFile` with `process.cwd()`, as it prevents common production bugs where `process.cwd()` does not point to the original source directories. However, because the imported object is cached in memory, any direct mutations to it will persist across future requests, unlike `JSON.parse` which provides a fresh clone per request.
**Action:** Always prefer direct static JSON imports over `fs.readFile` in Nuxt/Nitro deployments for static data, but ensure that any manipulations of this cached data use non-mutating methods (e.g., `Array.filter()`) or create safe clones to prevent unintended state sharing between requests.
